## 一、现有三层筛选的真实调用链

```
main.py GoldenPitApp.run_full_scan()
│
├─ 1. DataFetcher.get_stock_list()
│    └─ AKShareProvider.get_stock_list()
│       ├─ 主路径: ak.stock_zh_a_spot_em()      ← 本沙箱内持续 ConnectionError
│       └─ 降级路径: ak.stock_info_a_code_name() ← 只有 code+name 两列，
│                                                  PE/PB/市值等全部填 None
│
├─ 2. RadarScanner.scan(stock_list)              【第一层】
│    ├─ _apply_exclusions()     名称正则排除ST + 排除4/8开头代码
│    ├─ _filter_market_cap()    market_cap 全为 NaN → 整体跳过（fail-open ①）
│    ├─ _filter_roe()           pe_dynamic 全为 None → 整体跳过（fail-open ②）
│    ├─ _filter_drawdown()      change_60d/change_ytd 全为 None → 整体跳过，
│    │                          并填入 drawdown_52w=0 占位（fail-open ③）
│    └─ _filter_pe_percentile() pe_dynamic 无效 → 整体跳过（fail-open ④）
│    结果：5539 只 → 5332 只，仅名称/代码前缀排除生效，
│          五项"筛选"中四项被静默跳过
│
├─ 3. DeepScreener.screen(tier1.head(300))       【第二层】
│    └─ _check_stock() 逐项检查：
│       ├─ _check_fcf_quality()        PE缺失 → ok=False（fail-closed，正确）
│       ├─ _check_roic()               PE/PB缺失 → ok=False（fail-closed，正确）
│       ├─ _check_goodwill()           数据缺失 → ok=True "默认通过"（fail-open ⑤）
│       ├─ _check_margin_stability()   数据缺失 → ok=True "默认通过"（fail-open ⑥）
│       └─ _check_debt()               数据缺失 → ok=True "默认通过"（fail-open ⑦）
│    通过规则 = 5项中过3项 → 一只财务数据完全缺失的股票
│    可以靠 3 个"默认通过"直接进入观察池（fail-open ⑧：规则放大器）
│
├─ 4. CoreConfirmer.confirm(tier2)               【第三层】
│    ├─ _run_valuation()      PE≤0 → 返回默认值 score=5/odds=1.0（静默兜底 ⑨）
│    ├─ _run_scoring()        调用 scorer.score_all(symbol)，
│    │                        但 DimensionScorer.score_all 签名为 (symbol, basic_info)
│    │                        → basic_info=None → 全部返回基准分 5.0（接口错位 ⑩）
│    ├─ _run_risk_check()     调用 risk_checker.check_all(symbol)，
│    │                        同样缺 basic_info → PE=0 触发"当前亏损"红旗
│    │                        → risk_score≥6 → overall_risk_level="极高"
│    │                        → 所有股票被"极高风险"误杀（接口错位 ⑪，实测复现：
│    │                        000651 风险等级输出为"极高"）
│    └─ 确认门槛: odds≥2.0 且 confidence≥0.7 且 风险≠极高
│       → 数据缺失时 odds=1.0 → 全部不确认 → 第三层输出为空
│
└─ 5. 报告层 Excel/HTML 正常生成（但内容为空池或脏数据）
```

**核心结论**：现有系统不是"三层筛选"，而是"第一层名义筛选、第二层默认放行、第三层接口错位"。数据源一旦降级，产出即为噪声。

## 三、指标口径差异表（现有 vs 新口径）

| 指标 | 现有实现 | 新口径（第一层硬条件） | 处置 |
|------|----------|------------------------|------|
| PE | 东财"市盈率-动态"(pe_dynamic)，阈值 <50 | **PE(TTM) < 15，严格小于**；TTM归母净利润>0 才可计算；保存数据源与价格日期 | 重构 |
| 股息率 | 不存在 | **股息率(TTM) > 5%，严格大于**；仅计入除权除息日已发生且 ≤ as_of_date 的现金分红；预案不计入 | 新增 |
| 季度收入增速 | 不存在 | **Q2单季营收同比 > Q1单季营收同比，严格大于**；Q2单季=半年报累计−Q1 | 新增 |
| 季度利润增速 | 不存在 | **Q2单季归母净利润同比 > Q1单季，严格大于**；**只用归母净利润**，不混用净利润/扣非/EPS | 新增 |
| ROE | 用 1/PE 冒充（口径错误） | 退出第一层准入，保留为展示/证据字段 | 降级为展示 |
| 52周回撤 | 用60日涨跌幅冒充，缺失填0 | 退出第一层准入，保留为展示字段 | 降级为展示 |
| PE历史分位 | 名义存在（实际被跳过） | 退出第一层准入，移至第二层证据包 | 移至第二层 |
| 市值 | ≥50亿，缺失跳过 | **不再是硬条件**（新五项中无市值），保留为展示字段 | 降级为展示 |
| ST 排除 | 名称正则 | 名称正则 + 记录 is_st 标记；风险警示名单交叉验证留作增强 | 保留+增强 |
| as_of_date | 无 | **强制**：每次筛选携带 as_of_date、price_date、公告日期、报告期、抓取时间 | 新增 |
| 负基数同比 | 无处理 | 上年同期归母≤0 → NOT_COMPARABLE → TURNAROUND_WATCHLIST，不进雷达池 | 新增 |
| 半年报未披露 | 无处理 | → PENDING_Q2_REPORT，禁止用预告/预测替代 | 新增 |

**关键口径发现（必须写入文档）**：

1. `stock_yjbb_em` 的"净利润"字段按东财页面口径为**归属于母公司股东的净利润**，但接口文档未显式标注 → **必须与 `stock_financial_abstract` 的"归母净利润"抽样交叉验证后署名使用**；不一致时以 financial_abstract 为准。
2. 业绩报表为**累计值**（Q1累计、半年报累计），Q2单季=半年报累计−Q1，与新口径公式一致。
3. `stock_yjbb_em` 含 `最新公告日期` 列 → **支持 as_of_date 前视偏差控制**：公告日期 > as_of_date 的报告期数据必须视为不可得 → PENDING_Q2_REPORT。
4. 分红明细的"派息"为**每10股**口径，需 ÷10；"进度=预案"且除权除息日为 NaT 的不得计入 TTM 股息。

**第一层高效管线设计（基于实测可用接口）**：

```
批量阶段（4-6次调用覆盖全市场）:
  stock_info_a_code_name          → 全市场清单
  yjbb_em(当年Q1) + yjbb_em(当年H1)
  yjbb_em(上年Q1) + yjbb_em(上年H1) → Q1/Q2单季同比（全市场）
  → 硬条件③④⑤过滤 → 候选收窄至数百只

单股阶段（仅对候选，每只2-3次调用）:
  stock_financial_abstract        → 归母净利润TTM、EPS、交叉验证
  stock_zh_a_daily                → as_of_date 收盘价
  → PE_TTM 计算 → 硬条件①过滤

单股阶段（仅对PE通过者）:
  stock_history_dividend_detail   → TTM股息率 → 硬条件②过滤
```

预计单股调用量：数百只 × 3 次 ≈ 千次级，配合缓存可在 30 分钟内完成全量扫描。

## 九、需要您决定的参数与业务歧义

1. **科创板(688)是否排除？** 现代码注释说排除但实际未排除（④⑭）。建议：第一层不排除，仅在输出中标记板块；请您确认。

3. **PE(TTM) 股本口径**：东财现货接口在本环境不可用，PE_TTM 需自计算。自计算需要总股本——`stock_financial_abstract` 可由 归母净利润÷基本每股收益 推算（含稀释误差）；或固定取最新披露股本。两种口径都可能与行情软件有 ±2% 偏差，**是否接受自计算口径并在 source_lineage 中标注？**
4. **股息率分母**：用 as_of_date 收盘价（新浪日K，不复权）。历史回扫时若期间发生大额送转，未复权价格会失真——**历史回扫是否启用后复权价格，并在字段中标记？**
5. **yjbb "净利润" 与 financial_abstract "归母净利润" 抽样不一致时的裁决规则**：建议以 financial_abstract 为准并记录偏差，请确认。
6. **TURNAROUND_WATCHLIST 输出结构**：是否与雷达池同构（增加 turnaround_type 字段：亏损收窄/扭亏为盈）？
7. **营收同比的分母为零**：营收理论上不为负，但可能为 0（新上市/重组）→ 是否同样按 NOT_COMPARABLE 处理？
8. **第一层是否保留市值/流动性软性展示字段**（如成交额中位数），仅展示不筛选？
